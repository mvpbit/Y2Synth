# AGENTS.md — правила работы над Y2Synth

Этот файл предназначен для AI-агентов и разработчиков. Прочитай его вместе с [PROJECT](docs/PROJECT.md), [ARCHITECTURE](docs/ARCHITECTURE.md), [UI MENU](docs/UI_MENU.md), [ROADMAP](docs/ROADMAP.md) и [DEVELOPMENT](docs/DEVELOPMENT.md) **до** редактирования кода.

## Назначение и приоритеты

Y2Synth — экспериментальный музыкальный инструмент под будущий Innioasis Y2. На Mac уже звучит Rust-прототип: DrumsRNN, Synth 1 (Pluck/Pad), процедурная генерация нот и общая мастер-цепочка Delay → Reverb. Это пока не прошивка и не подтверждённый запуск на Y2. Пользователь решил остановить новые звуковые функции до приезда устройства.

**Ключевое пользовательское требование:** DrumsRNN создаёт барабанные ритмы самостоятельно, без подготовленного человеком грува или MIDI-подсказки. Один внутренний нулевой (тихий) bootstrap-шаг модели допустим: это часть алгоритма, а не пользовательский паттерн.

## Работа с репозиторием

- **Основная ветка разработки — `main`.** Пользователь явно выбрал прямую разработку в `main`; не создавай экспериментальные ветки и PR без необходимости или отдельной договорённости.
- Перед изменениями прочти актуальное состояние `main`, проверь затрагиваемые файлы и историю. Не перезаписывай чужие изменения.
- Делай небольшие тематические коммиты. Не переписывай историю `main` и не применяй force push.
- Если пользователь говорит «стой», немедленно останови изменения. Не продолжай действие без нового разрешения.
- После изменений честно перечисляй, что внесено, что реально проверено, а что требует проверки на Mac или устройстве.
- Не коммить скачанные веса модели, бинарные checkpoint shards, сборочные артефакты, аудиозаписи или секреты. `experiments/drumsrnn/rust/Cargo.lock` **нужно** сохранять в Git: это lockfile приложения/эксперимента.

## Архитектурные границы

- Разделяй **нейросетевой инференс**, **транспорт/секвенсор** и **генерацию аудио**.
- На аудиопути не должны выполняться инференс, файловый ввод-вывод, синтез полного такта или непредсказуемые блокирующие операции.
- Вычисляй новые паттерны и подготавливай звуковые буферы вне аудиопотока. Плановая смена паттерна и BPM — на границе такта. Следи за непрерывностью звучания.
- Реализацию, специфичную для macOS, изолируй от переносимого ядра. Целевая платформа Y2Linux ещё не проверена.
- Экспериментальный WAV-синтезатор не следует называть финальным аудиодвижком.

## Меню и состояние проекта

- Ориентируйся на [UI MENU](docs/UI_MENU.md): главный экран состоит из PLAY; нажатие центра открывает USER/AI; в AI есть Generate All и Generate Track, в USER три страницы. BACK возвращает на предыдущий уровень.
- `src/ui.rs` — **чистая машина состояний**, которая отдаёт `Command`; не включай сюда действия hardware, файловый ввод/вывод, сетевые запросы, AI-инференс и DSP. Она не выполняет генерацию сама.
- `src/project.rs` — типизированные независимые дорожки и сохранённый в RAM снимок; `GenerateTrack` заменяет только указанную дорожку. `GeneratedAll` должен применяться целиком **только после** успеха всех генераторов, чтобы не терять предыдущую музыку.
- `src/application.rs` — координатор команд `ui.rs`, DrumsRNN, отдельного `Synth1Generator`, проекта и `AudioPort`. Реализованы live-CLI, эмуляция колеса, USER Synth 1 и общая цепочка FX; **не перемещай генерацию, полный рендер или мастер-эффекты в CoreAudio callback**.
- AI-меню `GenerateTrack(Synth1)` теперь генерирует **автономную алгоритмическую** (не ML) мелодию или аккордовую фразу через отдельный `Synth1Generator`; никогда не называть этот генератор обученной нейросетью. USER Synth 1 уже звучит с Pluck/Pad. Synth 2 и `GenerateAll` остаются **NotImplemented**. `UnavailableSynth` относится к Synth 2 и не должен имитировать его реализацию.
- PLAY всегда использует `last_saved` без повторной AI/алгоритмической генерации. В RAM-снимок входят BPM, DrumKit, оба присутствующих музыкальных трека и **общие MasterEffects** (Delay/Reverb). Файловое сохранение между перезагрузками ещё не реализовано.
- После ошибок генерации/рендера/публикации прежнее сохранённое состояние должно оставаться неизменным. Тестируй это при любой переработке coordinator.
- При изменениях навигации обновляй тесты `ui.rs` и `project.rs` и документацию меню. Продолжай оставлять работающий CPAL callback изолированным.

## Общие мастер-эффекты и текущее направление

- `src/master_fx.rs` — **единственная** последовательная цепочка **(Drums + Synth 1) → Delay → Reverb**, располагается после микширования, а не на отдельных дорожках. В будущем Synth 2 идёт в тот же общий mix.
- `MusicProject.master_fx` и `ApplicationController::set_master_fx` хранят/применяют настройки вместе с RAM-снимком. `DelaySettings`: `steps` 1…8 (1/16 ноты), `feedback` 0…0.75, `wet` 0…1; `ReverbSettings`: `size/damping` 0…1, `wet` 0…1. Оба по умолчанию включены.
- После пользовательского A/B-отзыва wet изменён на **параллельное добавление** (`dry + wet × processed`), усилены comb-отражения. **Исправленный звук подтверждён пользователем**; не возвращай слабый wet/dry crossfade без обсуждения. Общая peak protection остаётся.
- FX рендерятся **offline на control thread**, используя 12-периодный pre-roll для хвостов; это может быть дорого для Y2. CPAL callback менять и удорожать нельзя. Проверять отсутствие xrun, длительную стабильность, mono/stereo и CPU/RAM на конкретном устройстве.
- `src/melody.rs` содержит процедурный (не обученный) композитор для Synth 1. Евклидовы алгоритмы высоты/длительности **пока не интегрированы**; не сообщай, что такой режим уже работает.
- **Следующая веха после паузы:** изучение реального Innioasis Y2, SoC/ABI, Linux-аудио и профилирование. Не утверждай, что есть аппаратный интерфейс, Synth 2, Generate All, файловое сохранение или завершённая прошивка.

## Отдельный интерфейсный Web Audio эксперимент (18 ноября 2026)

- `experiments/ui-prototype/index.html` — самостоятельный браузерный макет физического UI, а **не** движок устройства и не JavaScript/WASM-порт Rust. В его Web Audio нет обученной DrumsRNN, точного `melody.rs` или Rust master FX; не заявлять их эквивалентность.
- Прототип нужен для проверки PLAY/USER/AI, колеса, дисплея и общего MASTER FX; он не должен заменять переносимое ядро `ui.rs`, `application.rs` и `master_fx.rs`.
- Нативное разрешение Y2 **подтверждено документацией производителя: 480×360 px (2,4″, 4:3)**; UI в браузере **обязательно** проектировать в точной фиксированной сетке 480×360 без responsive-сжатия. Физические события колеса и точную аппаратную версию после приезда надо проверить отдельно.
- `experiments/ui-prototype/check-ui.mjs` проверяет размеры 480×360, полосы 36+292+32 и JS; `.github/workflows/pages-ui.yml` предназначен для автопубликации из `main` на Pages, без публикации весов модели. Первый CI тест прошёл, деплой ожидает **разового включения Pages** в Settings → Pages → Source: GitHub Actions. Не выдавать ожидаемый URL за уже живой до зелёного deployment. Слуховая/визуальная проверка в браузере ещё ожидается.

## Проверки

Из корня репозитория:

```bash
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml
cargo run --release --locked --manifest-path experiments/drumsrnn/rust/Cargo.toml --bin generate -- --steps 16 --temperature 1.2
```

Полный прогон генератора требует предварительно скачанного checkpoint. `--argmax` используется для детерминированной сверки с браузерным Magenta.js, а не для прослушивания: на известном тесте он выдал 16 шагов тишины.

**Актуальный статус 2026-11-17:** пользователь успешно прослушал Synth 1, а затем **одобрил обновлённый мастер Delay/Reverb** («всё отлично»). Последняя программа `live` на Mac звучала; полный лог `cargo test --locked --features live-audio`, профилирование и проверка на Innioasis Y2 **не предоставлены**. Для проверок используй точную команду из [README](README.md). `Cargo.lock` уже в `main`.
