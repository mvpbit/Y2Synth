# AGENTS.md — правила работы над Y2Synth

Этот файл предназначен для AI-агентов и разработчиков. Прочитай его вместе с [PROJECT](docs/PROJECT.md), [ARCHITECTURE](docs/ARCHITECTURE.md), [UI MENU](docs/UI_MENU.md), [ROADMAP](docs/ROADMAP.md) и [DEVELOPMENT](docs/DEVELOPMENT.md) **до** редактирования кода.

## Назначение и приоритеты

Y2Synth — экспериментальный музыкальный инструмент с двумя будущими синтезаторами, драм-машиной и локальной AI-генерацией ритмов на базе Innioasis Y2. Цель текущего этапа — воспроизводимая автономная генерация и воспроизведение барабанных паттернов на Rust, а не готовая прошивка.

**Ключевое пользовательское требование:** DrumsRNN создаёт барабанные ритмы самостоятельно, без подготовленного человеком грува или MIDI-подсказки. Один внутренний нулевой (тихий) bootstrap-шаг модели допустим: это часть алгоритма, а не пользовательский паттерн.

## Работа с репозиторием

- **Основная ветка разработки — `main`.** Пользователь явно выбрал прямую разработку в `main`; не создавай экспериментальные ветки и PR без необходимости или отдельной договорённости.
- Перед изменениями прочти актуальное состояние `main`, проверь затрагиваемые файлы и историю. Не перезаписывай чужие изменения.
- Делай небольшие тематические коммиты. Не переписывай историю `main` и не применяй force push.
- Если пользователь говорит «стой», немедленно останови изменения. Не продолжай действие без нового разрешения.
- После изменений честно перечисляй, что внесено, что реально проверено, а что требует проверки на Mac или устройстве.
- Не коммить скачанные веса модели, бинарные checkpoint shards, сборочные артефакты, аудиозаписи или секреты. `experiments/drumsrnn/rust/Cargo.lock` **нужно** сохранять в Git: это lockfile приложения/эксперимента.

## Архитектурные границы

- Разделяй **нейросетевой инференс**, **транспорт/секвенсор** и **генерацию аудио**.
- На аудиопути не должны выполняться инференс, файловый ввод-вывод, синтез полного такта или непредсказуемые блокирующие операции.
- Вычисляй новые паттерны и подготавливай звуковые буферы вне аудиопотока. Плановая смена паттерна и BPM — на границе такта. Следи за непрерывностью звучания.
- Реализацию, специфичную для macOS, изолируй от переносимого ядра. Целевая платформа Y2Linux ещё не проверена.
- Экспериментальный WAV-синтезатор не следует называть финальным аудиодвижком.

## Меню и состояние проекта

- Ориентируйся на [UI MENU](docs/UI_MENU.md): главный экран состоит из PLAY; нажатие центра открывает USER/AI; в AI есть Generate All и Generate Track, в USER три страницы. BACK возвращает на предыдущий уровень.
- `src/ui.rs` — **чистая машина состояний**, которая отдаёт `Command`; не включай сюда действия hardware, файловый ввод/вывод, сетевые запросы, AI-инференс и DSP. Она не выполняет генерацию сама.
- `src/project.rs` — типизированные независимые дорожки и сохранённый в RAM снимок; `GenerateTrack` заменяет только указанную дорожку. `GeneratedAll` должен применяться целиком **только после** успеха всех генераторов, чтобы не терять предыдущую музыку.
- `src/application.rs` — Application Controller: принимает команды `ui.rs`, использует `DrumGenerator` и `AudioPort`, сохраняет `MusicSession` и выдаёт `AppResponse`. `live.rs` уже подключён к нему для Drums и эмуляции колеса; **не перемещай эту работу в CoreAudio callback**.
- AI для Synth 1/2 и Generate All остаются **NotImplemented**, без замены проектных треков. `UnavailableSynth` запрещает имитировать реализацию синтезаторов.
- PLAY всегда использует `last_saved` без повторного AI-инференса. Общий BPM и DrumsKit входят в RAM-снимок; физическое сохранение между перезагрузками ещё не реализовано.
- После ошибок генерации/рендера/публикации прежнее сохранённое состояние должно оставаться неизменным. Тестируй это при любой переработке coordinator.
- При изменениях навигации обновляй тесты `ui.rs` и `project.rs` и документацию меню. Продолжай оставлять работающий CPAL callback изолированным.

## Проверки

Из корня репозитория:

```bash
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml
cargo run --release --locked --manifest-path experiments/drumsrnn/rust/Cargo.toml --bin generate -- --steps 16 --temperature 1.2
```

Полный прогон генератора требует предварительно скачанного checkpoint. `--argmax` используется для детерминированной сверки с браузерным Magenta.js, а не для прослушивания: на известном тесте он выдал 16 шагов тишины.

**Статус интеграции:** live-прототип с CPAL и `triple_buffer 9.0.0` пользователь подтвердил на Mac. Позже появились новый DSP и Application Controller с CLI-навигацией: **последнюю версию ещё нужно собрать и прослушать на Mac**. Запускай `cargo test --locked --features live-audio` и `cargo run --locked --features live-audio --bin live`. `Cargo.lock` уже в `main`.
