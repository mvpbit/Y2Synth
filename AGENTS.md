## Актуальное направление — 18 ноября 2026

Y2Synth — экспериментальный музыкальный инструмент для будущего Innioasis Y2. Пользователь возобновил работу над AI и выбрал модели **для браузера и Rust**:

- DRUMS: `drum_kit_rnn`.
- PLUCK: `melody_rnn`.
- PAD: `multitrack_chords`, с сохранением полифонии.

Ранее пользователь прослушал Rust-тембры и одобрил усиленный Delay/Reverb на Mac. Новая трёхдорожечная версия ещё требует прослушивания; запуск, память и скорость на Y2 не подтверждены. Старые записи о паузе, процедурном live AI и отсутствии второй Rust-дорожки относятся к предыдущей версии.

DrumsRNN создаёт ритм самостоятельно, без написанного человеком MIDI-грува. Один внутренний тихий bootstrap допустим; MelodyRNN использует такой же принцип.

## Репозиторий и работа с пользователем

- Основная ветка — **main**; пользователь разрешил прямую разработку. Не создавай ветки/PR без необходимости.
- В текущей сессии пользователь требует работать с кодом **только через подключение GitHub**, без локального checkout, файлов и локальных запусков. Проверки выполняются GitHub Actions.
- Перед изменением прочти актуальную версию, не перезаписывай чужие изменения. Делай тематические коммиты, без force push.
- На «стой» немедленно останови изменения до нового разрешения.
- Не коммить веса, бинарные shards, аудио, сборочные артефакты и секреты. Cargo.lock сохраняется в Git.
- Честно различай реализацию, автоматические проверки, пользовательское прослушивание и аппаратную проверку.

## Архитектурные границы

Нейросетевой инференс, музыкальное состояние, транспорт и DSP разделены. В CPAL callback запрещены загрузка/инференс, файловый I/O, рендер полного такта и мастер-эффекты. На control thread готовится PCM, lock-free triple buffer публикует его на границе такта. Не удорожать callback.

- `attention.rs` / `generation.rs`: существующий DrumsRNN, девять голосов.
- `neural.rs`: MelodyRNN и иерархический MusicVAE, lazy checkpoints, независимые seed-последовательности PLUCK/PAD. Scalar reference implementation; оптимизация ARM не выполнена.
- `lib.rs`: streaming-загрузчик float32 и uint8/uint16 quantization; фильтрация неиспользуемых весов MusicVAE.
- `synth1.rs`: общий renderer двух тембров и NoteEvent. Историческое имя модуля не означает единственную дорожку.
- `application.rs`: в AppProject **две реальные SynthTrack**. `dispatch_neural` фиксирует Synth1=PLUCK и Synth2=PAD. Старый `dispatch_with_synth` оставлен для совместимости и изолированных тестов.
- `melody.rs`: старый процедурный композитор, больше не live AI. Не называть его нейросетью.
- `ui.rs`: только InputEvent → Command; без моделей, файлов и DSP. В CLI показывать PLUCK/PAD, внутренние TrackId::Synth1/Synth2 пока сохранены.
- `sequencer.rs`: микс трёх дорожек до единой цепочки `master_fx.rs`.

Generate Track меняет только выбранную дорожку. Генерация/валидация/рендер/публикация должны завершиться до изменения current и last_saved. Ошибка сохраняет старую музыку. PLAY использует last_saved без повторной генерации. Проверять это при переработке координатора. Generate All остаётся NotImplemented; будущая реализация должна применять все дорожки атомарно.

PAD выбирает полифоническую небарабанную партию из MusicVAE и играет собственным тембром; модель генерирует ноты, не эффекты или аудио. Преобразование 96 → 16 шагов сохраняет одновременные ноты. Нельзя тихо подменять ошибку нейросети процедурными аккордами.

## Мастер-эффекты

Единственный тракт: **(DRUMS + PLUCK + PAD) → Delay → Reverb**. Пользователь одобрил параллельное добавление `dry + wet × processed`, усиленные comb-отражения и peak protection. Не возвращать слабый wet/dry crossfade без обсуждения.

MasterEffects входят в RAM-снимок. Delay: steps 1…8, feedback 0…0.75, wet 0…1. Reverb: size/damping/wet 0…1. Offline-рендер с 12-периодным pre-roll может быть дорогим для Y2. Стерео, xrun, latency/CPU/RAM ещё требуют измерений.

## Браузерный UI

`experiments/ui-prototype/` — отдельный Web Audio движок, не Rust/WASM-порт. Официальные Magenta.js 1.23.1 / TF.js 2.7.0 работают в `neural-worker.js`, веса загружаются по запросу с Google Storage, библиотеки с jsDelivr. Постоянного offline-кэша нет. Rust и Web Audio DSP звучат по-разному.

- Только названия PLUCK/PAD, без synth1/synth2 даже в HTML-идентификаторах.
- Весь видимый интерфейс **на английском**.
- HOME: только PLAY/PAUSE и вход в настройки через OK, без нотной сетки или редактирования шагов. Инструменты только AI-GENERATED; без USER, демо и стартовых партий. Сохранять уровни инструментов. Экран MASTER FX не менять в рамках этого UI-упрощения.
- Фиксированный дисплей **480×360 CSS px**, полосы 36+292+32; не сжимать responsive-правилами.
- Единый шрифт; все параметры MASTER FX помещаются без вертикальной прокрутки.
- Одно click-wheel: Return сверху, Previous слева, Next справа, Play/Pause (долгое Stop) снизу, OK в центре. Вращение мышью/touch/trackpad. Число редактируется после OK.
- Новая партия при PLAY применяется на границе такта; ошибки, timeout и устаревшие результаты не уничтожают ноты.
- `check-ui.mjs` проверяет UI, адаптер нот и async-жизненный цикл с mock worker; это не замена реальной генерации и прослушиванию.
- `.github/workflows/pages-ui.yml` публикует HTML и оба neural JS-файла в [GitHub Pages](https://mvpbit.github.io/Y2Synth/). Веса в Pages не копируются.

## Проверки и документация

`.github/workflows/rust-models.yml` выполняет release cargo test с live-audio, скачивает три checkpoint, получает эталон официального Magenta.js и сравнивает нативные Argmax-токены, затем проверяет случайную генерацию. Эталон относится к конкретной траектории, а не доказывает полную численную эквивалентность.
