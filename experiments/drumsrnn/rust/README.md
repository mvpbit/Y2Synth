# DrumsRNN Rust autonomous generator (experiment)

This crate contains an offline Magenta.js checkpoint loader, a native Rust three-layer LSTM/attention inference engine, an **autonomous drum-pattern generator**, and a minimal PCM16 WAV preview renderer. It is **not** Y2 firmware or a production drum synthesizer.

The weights must already exist from the repository's `experiments/drumsrnn/download-model.sh`.
The loader reads `config.json`, `weights_manifest.json`, and all referenced binary
shards; checks lengths, tensor names, shape overflow, float32 dtype and finite data;
then decodes actual weights into Rust `Vec<f32>` tensors. A scalar BasicLSTMCell step uses TensorFlow's `i,j,f,o` gate order and runtime `forget_bias=1.0`, with buffers reused across steps.

## Run from the Y2Synth repository root

```bash
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml
```

To override the default checkpoint path:

```bash
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml -- /path/to/drum_kit_rnn_tfjs
```

Expected for the checkpoint already inspected on Mac:

- 16 tensors
- 2,967,850 float32 elements
- 11,871,400 decoded weight bytes (11.32 MiB)
- attention length 32

**Still not verified:** new CPAL live output, strict real-time safety, controlled runtime benchmarks, cross-compilation, or running on Innioasis Y2. Production drum DSP is not implemented. The WAV renderer is a simple preview, not the final instrument. Loading and decoding all weights uses RAM; embedded suitability has not been established.

The checkpoint-loader tests and LSTM tests use synthetic small matrices; do not mistake a passing unit test for proof of full neural network equivalence. `cargo run --release` loads the real checkpoint and runs **one step per pretrained LSTM layer with a synthetic zero input vector**, which validates finite computations and compatible dimensions, **not a real generated drum event**. Next we need to build the attention wrapper and compare full inference against Magenta.js.

No model weights are committed to Git. `Cargo.lock` for this executable will be
generated by Cargo on the first local build and should subsequently be committed for
reproducible dependency resolution.

## Experimental attention-forward check

The `attention.rs` module follows `magenta-js/music/src/music_rnn/attention.ts`:
- 512 one-hot drum class + 6 signed binary counter values (`-1/+1`, least-significant bit first);
- input projection incorporating previous attention;
- three recurrent 256-wide `BasicLSTMCell` layers;
- 32-slot attention over previous output vectors, queried using all `c/h` states;
- output projection and `512` class logits.

The saved `attention/bias` tensor is loaded and checked but **not applied**
to the attention query, because the original Magenta.js `attention.ts` only
uses `tf.matMul(attnQuery, attnMatrix)` there.

The checkpoint-inspection CLI runs a first forward step after a silent bootstrap and prints the top-five next-class probabilities. **These five probabilities matched Magenta.js to six decimals.** The independent `--bin generate` program additionally makes complete autonomous patterns.

For numerical comparison without exporting JSON, open `reference.html` in **From scratch + Argmax** mode. Both CLI and page display top-five class probabilities on steps 0, 1, 7, 15. The first-step probabilities are independent of later random sampling.

Run:

```bash
git pull --ff-only
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml
```

**Verified on Mac:** the previous 14 tests passed; release loading and three LSTM + attention computations succeeded. Both implementations chose 16 silent classes under Argmax, and the top-five probabilities at steps 0, 1, 7, 15 matched to approximately 1e-6. This is strong evidence of correct multi-step behavior, not a comparison of every one of the 512 probabilities per step.

## Autonomous generation CLI (experimental)

The new `src/generation.rs` and `src/bin/generate.rs` provide a standalone
**from-scratch** 16-step drum generator using the same Magenta checkpoint;
no user-written groove or browser is needed.

```bash
# In the root of the Y2Synth repository
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --bin generate -- --steps 16 --temperature 1.2

# Deterministic option for comparison with browser's "Argmax":
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --bin generate -- --steps 16 --argmax

# Repeat identical pseudorandom sampling within Rust:
cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --bin generate -- --steps 16 --temperature 1.2 --seed 1234
```

The CLI prints sample time, an ASCII drum-grid, MIDI pitches/steps and
diagnostic top-five next-class probabilities at steps **0, 1, 7, 15**.
Pitch classes match the upstream Magenta default nine drum families:
`[36,38,42,46,45,48,50,49,51]`; class `0` means silence.

The internal **one silent-step seed** is fed to the model once. It is not
part of the output and is not a musician-provided pattern. The generated
class from each step is fed back for the following recurrent step.
`--temperature` samples a categorical distribution, `--argmax` chooses
the most probable class, and `--seed` provides repeatability for Rust.
The Rust sampling RNG is **not identical** to TensorFlow.js's RNG, so
temperature sampling is not expected to match the browser event-for-event.

**Validation status:** Rust loaded the checkpoint and created a 16-step, 9-hit pattern in **40.2 ms** at temperature 1.2 in one Mac test run. Under Argmax, Rust and Magenta.js chose the same 16 classes (all silent), with top-five probabilities matching to around 1e-6 on steps 0, 1, 7, 15. This does not establish full numerical equivalence or hardware performance on Y2.

Model speed on 32-bit ARM, full 512-class numerical equality across all steps, production audio, and Y2 firmware integration remain out of scope.

## Listen to a pattern generated entirely on Rust (new, untested on Mac)

`src/audio.rs` adds a **dependency-free, synthesized WAV preview**.
It turns the existing MIDI-like events into basic kick/snare/hi-hat/tom/cymbal
voices using standard-library math and writes a 44.1 kHz, mono, 16-bit PCM WAV.
This is only for hearing the generated timing, not production DSP.

From the Y2Synth repo root on macOS:

```bash
git pull --ff-only
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml

cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --bin generate -- --steps 16 --temperature 1.2 \
  --wav /tmp/y2synth-groove.wav --bpm 120

afplay /tmp/y2synth-groove.wav
```

No browser, TensorFlow.js, or JSON is involved. The `--wav` argument is
optional, so the original text-only CLI remains unchanged by default.
`--bpm` accepts 40–240 and defaults to 120. Use `--seed` to replay a
specific Rust-generated rhythm. If a sampled pattern has zero hits, the WAV
will contain silence; run the stochastic sampler again.

**Validation status:** new WAV code and its 5 unit tests have been committed,
but have **not yet been compiled or auditioned** on the user's Mac.

## Live drum machine (new, Mac verification pending)

An interactive experimental macOS output app has been added:
- portable `src/sequencer.rs` prepares 16-step loops, switches a new buffer on the next bar, and fades transitions;
- `src/bin/live.rs` opens the default output device with `cpal 0.18.2` (CoreAudio on macOS), sends precomputed mono samples to all output channels, and accepts commands from stdin;
- model inference, pattern generation and loop rendering run on the CLI/control thread, never inside the audio callback.

**Code status:** this is the first implementation and **has not yet been compiled, tested or auditioned on the user's Mac**. The `sequencer.rs` module is now exported from `lib.rs`, so its unit tests will run with ordinary `cargo test`; the live binary needs the opt-in feature `live-audio`.

From the Y2Synth repository root:

```bash
git pull --ff-only

# First build resolves CPAL and updates the existing Cargo.lock.
# DO NOT use --locked until you have committed the updated lockfile.
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --features live-audio

cargo run --release --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --features live-audio --bin live -- --bpm 120 --temperature 1.2
```

Then enter in the interactive terminal:

```text
play
regenerate
bpm 140
stop
play
status
quit
```

`play` starts a repeating 16-step loop, `stop` fades out, `bpm N` prepares the existing groove at a new tempo, and `regenerate` asks the AI for a completely new pattern *without user MIDI input*. New buffers are scheduled on a bar boundary when playback is running. There is no intermediate WAV file.

After successful compilation and testing, commit the changed `experiments/drumsrnn/rust/Cargo.lock` to `main` (do **not** add downloaded model weights or WAV files). Then normal commands may again use `--locked`.

**Real-time caveat:** `std::sync::mpsc` command polling and freeing old buffers in the audio callback may still involve internal locks or allocation/deallocation. This is an exploratory preview, not a formally RT-safe audio engine. Further hardening, device routing, xrun/latency benchmarks, and ARM/Y2Linux compatibility remain future work.
