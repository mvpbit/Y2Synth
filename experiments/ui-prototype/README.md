# Y2Synth — браузерный прототип интерфейса

**Состояние: 18 ноября 2026.** Отдельный прототип для проектирования интерфейса **до получения Innioasis Y2**. Входной файл `index.html`; приложение статическое, без backend. Нейросети используют pinned-библиотеки Magenta.js 1.23.1 / TensorFlow.js 2.7.0 и checkpoints Google Storage. Дополнительно созданы статический тест `check-ui.mjs` и workflow автопубликации `.github/workflows/pages-ui.yml`.

**Нативное разрешение дисплея Innioasis Y2: 480 × 360 пикселей (2,4″, 4:3)** — [официальная спецификация](https://www.innioasis.com/a/docs/y2/specifications). Область `#native-screen` **строго** 480×360 CSS-пикселей (header 36 + main 292 + footer 32). Экран не уменьшается в responsive layout, даже если окно браузера уже: страницу можно горизонтально прокрутить. Это точная логическая координатная сетка дисплея; *физический размер на мониторе Mac* зависит от плотности пикселей и масштаба браузера и не обязан равняться 2,4″.

## Шрифт и экран MASTER FX

Текст меню, подписи, значения и строки состояния используют единый системный шрифт **12 px / 16 px**. Крупная надпись PLAY остаётся акцентом главного экрана. На MASTER FX все восемь параметров видны одновременно: строки высотой 26 px, интервалы 2 px, единицы Delay показаны рядом со значением (`2 × 1/16`). Список занимает 222 px внутри доступной области 272 px; заголовок и подсказка также помещаются. Вертикальная прокрутка меню и автоматический `scrollIntoView` убраны.

## GitHub Pages: автоматическая публикация

Прототип публикуется **из исходников того же репозитория `mvpbit/Y2Synth`**, без ручного копирования. Workflow [`.github/workflows/pages-ui.yml`](../../.github/workflows/pages-ui.yml) при каждом push в `main`, меняющем `experiments/ui-prototype/**` или сам workflow, выполняет:

1. `node experiments/ui-prototype/check-ui.mjs` — проверяет **480×360**, разбиение экрана 36+292+32 и синтаксис встроенного JavaScript.
2. Собирает статический сайт: копирует `index.html`, `neural-common.js` и `neural-worker.js` в `_site/`, создаёт `.nojekyll` (веса DrumsRNN, код Rust и прочие файлы репозитория **не публикуются**).
3. `actions/configure-pages` → `upload-pages-artifact` → `deploy-pages`; используется стандартный `GITHUB_TOKEN` с ограниченными `pages:write` и `id-token:write`. Секретов и PAT не нужно.

**GitHub Pages активирован и работает.** Автопубликация из `main` подтверждена успешными workflow-запусками. Адрес живого прототипа: **https://mvpbit.github.io/Y2Synth/**. При редактировании HTML `main` новый сайт публикуется автоматически после успешного теста; смотреть результаты в [Actions](https://github.com/mvpbit/Y2Synth/actions/workflows/pages-ui.yml).

## Запуск на Mac Studio

Из корня репозитория:

```bash
git pull --ff-only
python3 -m http.server 8765 --bind 127.0.0.1
```

Открыть в браузере:

**http://127.0.0.1:8765/experiments/ui-prototype/index.html**

Затем нажать **PLAY**: это пользовательский жест, который разрешает браузеру запустить Web Audio API. Открывать через HTTP(S): Web Worker не рассчитан на прямой запуск через `file://`.

## Колесо как у настоящего Innioasis Y2

Ориентир — [официальное руководство](https://www.innioasis.com/a/docs/y2/device-overview): **сенсорное кольцо с четырьмя кнопками и центральным OK**. Три внешние кнопки PLAY/BACK/HOME удалены. Форма и расположение кнопок приблизительно повторяют оригинал (точные физические размеры колеса пока не измерены); сам **экран строго 480×360 CSS-пикселей**.

- **Верхняя ↩ Return:** вернуться назад; когда редактируется значение — выйти из режима редактирования.
- **Левая ⏮ Previous / правая ⏭ Next:** перемещаться по пунктам меню; во время редактирования — уменьшать/увеличивать число. На главном экране — вход в настройки, без перемотки шагов.
- **Нижняя ▶Ⅱ:** короткое нажатие **PLAY/PAUSE**, длительное удержание (650 мс) — **STOP** и сброс позиции.
- **Центр OK:** открыть настройки/выбрать пункт; на числовом параметре начать редактирование, повторное OK — принять значение.
- **Вращение кольца:** вести мышь или палец **по открытому участку кольца между кнопками**, по часовой стрелке — вниз/больше, против — вверх/меньше. 22,5° дуги — один шаг. Дополнительно поддерживается колесо мыши / тачпад над кольцом. В обычном меню вращение меняет выделение, после OK на параметре изменяет его значение.

Клавиатура: **Space** Play/Pause · **Enter** OK · **↑/↓** вращение · **←/→** Previous/Next · **Esc** Return · **H** Home (только вспомогательная клавиша в браузере).

Звуковой движок остаётся имитацией Web Audio, физические сигналы GPIO/драйвера реального колеса на Y2 пока не проверены. Статический тест `check-ui.mjs` проверяет геометрию экрана, расположение зон на кольце, работу жеста, редактирование числовых значений, независимые Pluck/Pad и сброс транспорта; он прошёл в GitHub Actions, но **живое тестирование нового колеса пользователем ещё предстоит**.

## Главный экран и инструменты

На HOME — одна экранная кнопка **PLAY / PAUSE** и подсказка **OK → settings**. Нотная сетка, кликабельные шаги и ручной ввод партий удалены. Центр колеса открывает настройки; Previous/Next и вращение на HOME также открывают меню, не перемещают позицию секвенсора.

В `PLAY SETTINGS` пять пунктов в порядке **DRUMS → PAD → PLUCK → FX → TEMPO**. Инструменты открываются прямо отсюда, без промежуточного AI-GENERATED. BACK со страницы любого инструмента возвращает сразу в настройки. У каждого доступна генерация своей моделью; у DRUMS/PAD/PLUCK есть регуляторы LEVEL. Раздела USER, демонстрационных партий и возврата к демо нет. Все дорожки изначально пустые; PLAY до первой успешной генерации предлагает создать инструмент в настройках. Модели не запускаются без выбора пользователя. Сначала генерируется PAD; затем становится доступна генерация PLUCK. В PLAY SETTINGS у DRUMS/PAD/PLUCK показаны только названия; подписи сохранены у FX (Delay → Reverb) и TEMPO (BPM). Тональность остаётся в сообщении о генерации.

`PLAY SETTINGS → FX` и `TEMPO` доступны отдельно. Экран эффектов, восемь параметров, их оформление и DSP не менялись.

## Генерация партий в браузере

| Дорожка | Checkpoint | Результат |
| --- | --- | --- |
| DRUMS | `music_rnn/drum_kit_rnn` | Автономный ритм, внутренний тихий bootstrap |
| PLUCK | `music_rnn/melody_rnn` | Монофоническая мелодия |
| PAD | `music_vae/multitrack_chords` | Полифоническая небарабанная партия под выбранный аккорд |

Инференс выполняется в `neural-worker.js`, отдельно от UI и планирования аудио. Модели создаются независимо и загружаются по запросу с официального Google Storage. При первом использовании нужен интернет; постоянного offline-кэша приложение пока не реализует. Используется Offscreen WebGL, где он доступен, иначе CPU. Повторная генерация использует загруженную модель.

PAD случайно выбирает тональность из всех 12 тоник × major/minor, исключая предыдущую при перегенерации. MusicVAE получает тонический аккорд выбранной тональности. Модель выдаёт до восьми партий по 64 performance-токена, с музыкальной сеткой 24 шага/четверть (96/такт). Адаптер переводит её в наши 16 шагов и выбирает полифоническую небарабанную дорожку, сохраняя одновременные ноты; не достраивает придуманные аккорды при неудаче модели. PAD приводится к выбранной гамме и ограничен шестью голосами/48 нотами. MelodyRNN создаёт исходную мелодию PLUCK; гармонический адаптер подбирает её опорные и длинные ноты из текущих голосов PAD, а короткие проходящие — из общей гаммы. Длинные ноты разделяются при смене гармонии PAD. Это музыкальная постобработка, а не chord conditioning внутри MelodyRNN.

При перегенерации PAD существующая мелодия PLUCK подстраивается автоматически. Исходные модельные ноты сохраняются отдельно; повторные перестройки не накапливают квантование. PAD, его тональность и PLUCK применяются вместе на границе такта; ошибка не меняет ни одну из дорожек. PLUCK/DRUMS не изменяют PAD.

DrumsRNN имеет девять барабанных классов; браузерный движок отображает их на существующие KICK/SNARE/HAT. Rust сохраняет все девять голосов.

Пустой/неподходящий результат повторяется до трёх попыток. Ошибка сети, модели или timeout 180 секунд оставляет старую музыку. Одновременно идёт только одна генерация. Новая партия во время PLAY устанавливается на границе такта; при остановке — сразу. Ответы устаревших запросов игнорируются. Процедурной подмены AI нет.

`check-ui.mjs` проверяет эти переходы с имитацией worker, преобразование полифонии и ритмической сетки, геометрию/колесо, огибающие и независимость дорожек. Реальная генерация всех трёх моделей также проверена на GitHub Pages.

## Громкость барабанной дорожки

На странице DRUMS под GENERATE DRUMS добавлен LEVEL: 0.00–1.00, шаг 0.05. OK включает редактирование, колесо меняет уровень. Отдельный GainNode управляет KICK, обеими составляющими SNARE и HAT до общего микса и эффектов. Изменения сглаживаются; 0 отключает новый сигнал барабанов. По умолчанию 1.00 сохраняет прежнюю громкость. Перегенерация ритма сохраняет выбранный уровень, PLUCK/PAD не меняются.

## Аудиосхема браузера

```text
Drums (Web Audio) ---+
PLUCK ------+-- mix --+----------------+---- dry -----+
PAD --------+         |                |              |
                                +-- Delay (feedback) -- wet ---> Reverb input
                                                       |           |
                                                       +--------> Convolver wet
                                                                   |
                                Reverb dry ------------------------+--> limiter --> output
```

Delay синхронизирован с BPM, Reverb использует сгенерированный импульс для `ConvolverNode`; оба включаются/отключаются и имеют регулируемые параметры. Эффекты обрабатывают общий микс, а не каждую дорожку отдельно.

**Web Audio и Rust используют разные DSP-реализации.** Браузерный Reverb — `ConvolverNode`, Rust — comb/all-pass. Совпадение звучания не обещается. В обеих версиях есть независимые PLUCK и PAD, но браузер не вызывает Rust. В HTML используются только идентификаторы `pluck` и `pad`.

**Состояние хранится в RAM** и сбрасывается при закрытии страницы. Generate All, MIDI I/O, постоянное сохранение и драйверы настоящего Y2 не реализованы.
