# Y2Synth — браузерный прототип интерфейса

**Состояние: 18 ноября 2026.** Отдельный прототип для проектирования интерфейса **до получения Innioasis Y2**. Входной файл `index.html`, без внешних зависимостей, npm и backend. Дополнительно созданы статический тест `check-ui.mjs` и workflow автопубликации `.github/workflows/pages-ui.yml`.

**Нативное разрешение дисплея Innioasis Y2: 480 × 360 пикселей (2,4″, 4:3)** — [официальная спецификация](https://www.innioasis.com/a/docs/y2/specifications). Область `#native-screen` **строго** 480×360 CSS-пикселей (header 36 + main 292 + footer 32). Экран не уменьшается в responsive layout, даже если окно браузера уже: страницу можно горизонтально прокрутить. Это точная логическая координатная сетка дисплея; *физический размер на мониторе Mac* зависит от плотности пикселей и масштаба браузера и не обязан равняться 2,4″.

## Шрифт и экран MASTER FX

Текст меню, подписи, значения и строки состояния используют единый системный шрифт **12 px / 16 px**. Крупная надпись PLAY остаётся акцентом главного экрана. На MASTER FX все восемь параметров видны одновременно: строки высотой 26 px, интервалы 2 px, единицы Delay показаны рядом со значением (`2 × 1/16`). Список занимает 222 px внутри доступной области 272 px; заголовок и подсказка также помещаются. Вертикальная прокрутка меню и автоматический `scrollIntoView` убраны.

## GitHub Pages: автоматическая публикация

Прототип публикуется **из исходников того же репозитория `mvpbit/Y2Synth`**, без ручного копирования. Workflow [`.github/workflows/pages-ui.yml`](../../.github/workflows/pages-ui.yml) при каждом push в `main`, меняющем `experiments/ui-prototype/**` или сам workflow, выполняет:

1. `node experiments/ui-prototype/check-ui.mjs` — проверяет **480×360**, разбиение экрана 36+292+32 и синтаксис встроенного JavaScript.
2. Собирает статический сайт: копирует **только** `index.html` в `_site/index.html`, создаёт `.nojekyll` (веса DrumsRNN, код Rust и прочие файлы репозитория **не публикуются**).
3. `actions/configure-pages` → `upload-pages-artifact` → `deploy-pages`; используется стандартный `GITHUB_TOKEN` с ограниченными `pages:write` и `id-token:write`. Секретов и PAT не нужно.

**GitHub Pages активирован и работает.** Автопубликация из `main` подтверждена успешными workflow-запусками. Адрес живого прототипа: **https://mvpbit.github.io/Y2Synth/**. При редактировании HTML `main` новый сайт публикуется автоматически после успешного теста; смотреть результаты в [Actions](https://github.com/mvpbit/Y2Synth/actions/workflows/pages-ui.yml).

## Запуск на Mac Studio

Из корня репозитория:

```bash
git pull --ff-only
python3 -m http.server 8765 --bind 127.0.0.1
```

Открыть в браузере:

**http://127.0.0.1:8765/experiments/ui-prototype/index.html**

Затем нажать **PLAY**: это пользовательский жест, который разрешает браузеру запустить Web Audio API. Можно также открыть `index.html` непосредственно как локальный файл, но локальный HTTP-сервер удобнее для отладки.

## Колесо как у настоящего Innioasis Y2

Ориентир — [официальное руководство](https://www.innioasis.com/a/docs/y2/device-overview): **сенсорное кольцо с четырьмя кнопками и центральным OK**. Три внешние кнопки PLAY/BACK/HOME удалены. Форма и расположение кнопок приблизительно повторяют оригинал (точные физические размеры колеса пока не измерены); сам **экран строго 480×360 CSS-пикселей**.

- **Верхняя ↩ Return:** вернуться назад; когда редактируется значение — выйти из режима редактирования.
- **Левая ⏮ Previous / правая ⏭ Next:** перемещаться по пунктам меню; во время редактирования — уменьшать/увеличивать число. На главном экране — шаг назад/вперёд в 16-шаговом паттерне (решение браузерного прототипа).
- **Нижняя ▶Ⅱ:** короткое нажатие **PLAY/PAUSE**, длительное удержание (650 мс) — **STOP** и сброс позиции.
- **Центр OK:** открыть настройки/выбрать пункт; на числовом параметре начать редактирование, повторное OK — принять значение.
- **Вращение кольца:** вести мышь или палец **по открытому участку кольца между кнопками**, по часовой стрелке — вниз/больше, против — вверх/меньше. 22,5° дуги — один шаг. Дополнительно поддерживается колесо мыши / тачпад над кольцом. В обычном меню вращение меняет выделение, после OK на параметре изменяет его значение.

Клавиатура: **Space** Play/Pause · **Enter** OK · **↑/↓** вращение · **←/→** Previous/Next · **Esc** Return · **H** Home (только вспомогательная клавиша в браузере).

Звуковой движок остаётся имитацией Web Audio, физические сигналы GPIO/драйвера реального колеса на Y2 пока не проверены. Статический тест `check-ui.mjs` проверяет геометрию экрана, расположение зон на кольце, работу жеста, редактирование числовых значений, независимые Pluck/Pad и сброс транспорта; он прошёл в GitHub Actions, но **живое тестирование нового колеса пользователем ещё предстоит**.

`PLAY → OK → PLAY SETTINGS → USER` — **PLUCK** (мелодии), **PAD** (аккорды), Drums. У каждого синтезатора свой уровень, ноты, генерация и возврат к демонстрационной партии. **Выбора пресета в меню больше нет.**

`PLAY → OK → PLAY SETTINGS → AI → GENERATE TRACK` — отдельная браузерная процедурная генерация **PLUCK**, **PAD** или Drums. Выбранная дорожка меняется независимо от двух остальных.

`PLAY → OK → PLAY SETTINGS → MASTER FX` — общие Delay/Reverb.

На главном экране показана 16-шаговая сетка из **пяти строк: KICK, SNARE, HAT, PLUCK и PAD**. Нижняя поясняющая подпись удалена в пользу второй синт-дорожки. **PLUCK и PAD — постоянные самостоятельные инструменты**, без номеров и переключения пресета. Обе браузерные дорожки имеют свои 16-шаговые партии и могут звучать одновременно; PAD больше не пустой placeholder. Клетки барабанов кликабельны; обе партии изменяются через собственные страницы USER и AI. Строки синтезаторов пока отображают события нот, но прямой редактор их клеток ещё не реализован. Все пять строк помещаются в фиксированную область дисплея 480×360.

## Аудиосхема браузера

```text
Drums (Web Audio) ---+
Synth 1 (Pluck) ------+-- mix --+----------------+---- dry -----+
Synth 2 (Pad) --------+         |                |              |
                                +-- Delay (feedback) -- wet ---> Reverb input
                                                       |           |
                                                       +--------> Convolver wet
                                                                   |
                                Reverb dry ------------------------+--> limiter --> output
```

Delay синхронизирован с BPM, Reverb использует сгенерированный импульс для `ConvolverNode`; оба включаются/отключаются и имеют регулируемые параметры. Эффекты обрабатывают общий микс, а не каждую дорожку отдельно.

**Это имитация, не порт настоящего DSP:** браузерные ударные, Pluck и Pad реализованы лёгкими Web Audio голосами. **На уровне Rust пока есть только Synth 1 с переключаемыми пресетами Pluck/Pad; отдельного Rust Synth 2 ещё нет.** В этом HTML-проекте никаких идентификаторов `synth1`/`synth2` уже нет: используются `state.pluck`, `state.pad`, страницы `pluck`/`pad`, параметры `pluckLevel`/`padLevel` и соответствующие метки событий сетки. Зафиксированное распределение двух дорожек пока относится только к браузерному прототипу и концепции будущего UI. `GENERATE TRACK → DRUMS` не вызывает Magenta DrumsRNN; `GENERATE TRACK → PLUCK` и `GENERATE TRACK → PAD` используют упрощённые музыкальные алгоритмы, а не Rust-`melody.rs`. Браузерный Reverb — `ConvolverNode`, в то время как Rust-`master_fx.rs` применяет comb/all-pass. Поэтому точного совпадения звучания ожидать не нужно. Не заявлять численную эквивалентность.

**Состояние не сохраняется на диск**; закрытие страницы сбрасывает текущие партии/настройки. Не реализованы **Synth 2 в Rust-движке**, Generate All, аппаратные события Y2, настоящий экранный драйвер, MIDI I/O и интеграция с Rust; **браузерный PAD уже реализован**. Web Audio доступен через аудиовыход браузера.

## Проверка и цель

- **GitHub Actions подтвердил PASS** для статических проверок HTML/JavaScript и нативных размеров 480×360; шаг развертывания ожидает разового включения Pages в настройках репозитория.
- **Браузерный запуск и живое аудиотестирование пользователем ещё не подтверждены.** Следующее действие — открыть страницу, проверить PLAY, меню через колесо, отдельные дорожки и эффект wet/dry.
- После осмотра согласовать структуру главного экрана, размер шрифта, компоновку меню и назначение действий колеса. **Разрешение 480×360 известно из официальной спецификации**, но аппаратные события колеса, производительность и точная версия конкретного Y2 ещё предстоит подтвердить после приезда.
