# Y2Synth — актуальное состояние разработки

**Дата последней ревизии:** 2026-11-17. Этот документ создан для передачи контекста между чатами и разработчиками. Актуальные факты всегда сверяйте с кодом `main`.

## Git и принятые решения

- Репозиторий: `mvpbit/Y2Synth`, основная рабочая ветка **`main`**.
- Исследовательская ветка `research/magenta-drumsrnn-feasibility` ранее смержена и удалена. По просьбе пользователя новые экспериментальные изменения идут сразу в `main` без PR.
- Весовые файлы checkpoint остаются локальными; **не коммитить**. CPAL уже зафиксирован в `Cargo.lock`, но после добавления нового `triple_buffer` lockfile нужно снова обновить и закоммитить.
- Концепция: два синтезатора и драм-машина; текущая реализация фокусируется только на автономных AI-барабанах.
- AI должен генерировать с нуля, без исходного ритма пользователя; один *внутренний* тихий bootstrap-шаг допустим.

## Проверенные результаты

- Checkpoint Magenta DrumsRNN: 16 тензоров, 2 967 850 float32-параметров (~11,32 MiB).
- Rust: собственный loader, три LSTM-слоя, attention, 512-классовый выход, temperature / argmax и декодирование девяти барабанных классов.
- Пример успешной генерации 16 шагов при temperature 1.2: 9 MIDI-ударов за ~40,2 мс на Mac (разовый замер, **не** бенчмарк).
- Проверка Rust vs Magenta.js в режиме `From scratch / Argmax`: все 16 классов идентичны (нули, тишина); top-5 вероятности на шагах 0/1/7/15 отличаются примерно на 10⁻⁶. Это не доказывает совпадения всех 512 вероятностей на каждом шаге.
- Пользователь подтвердил, что Rust WAV-рендерер создал файл, который удалось прослушать на Mac.
- **2026-11-17:** пользователь сообщил «Работает» после команд проверки сборки и запуска интерактивного live-прототипа с CPAL. Это подтверждает первый рабочий live-запуск на Mac; результаты отдельного тестирования `regenerate`, `bpm`, `stop` и длительной работы пока не записаны.

## Live CLI: запланированная проверка на Mac

```bash
git switch main
git pull --ff-only

# Без --locked при первом запуске: новая зависимость triple_buffer ещё не внесена в Cargo.lock.
cargo test --manifest-path experiments/drumsrnn/rust/Cargo.toml --features live-audio

  --features live-audio --bin live -- --bpm 120 --temperature 1.2
```

В интерактивном терминале:

```text
play
regenerate
bpm 140
stop
play
quit
```

Текущая реализация готовит новый AI-паттерн и звуковой цикл на основном потоке CLI; пока этот поток рассчитывает ритм, аудио-CPAL callback читает старый подготовленный буфер. Команда `regenerate` не требует исходного грува пользователя. Не путать отсутствие промежуточного WAV с отсутствием *заранее подготовленных в памяти* PCM-буферов.

После успешной сборки необходимо зафиксировать обновлённый `Cargo.lock` в `main`; затем можно вернуть `--locked`. В активном callback больше не используются `std::sync::mpsc` и операции владения/освобождения `Vec`; вместо них `triple_buffer::Output` и `AtomicBool`. Это пока не доказательство полного отсутствия xrun: нужны реальные замеры и мониторинг CoreAudio.

## Эксперимент — lock-free аудиопоток после первого работающего live-прототипа (2026-11-17)

**Коммиты в `main` внесены, Mac-регрессия ещё не выполнена.**

- `src/sequencer.rs` содержит только подготовку звукового такта. Это контрольный поток, допускающий аллокации.
- Добавлен `src/realtime.rs` и опциональный `triple_buffer = 9.0.0`.
- В `live.rs` убран `std::sync::mpsc`; управление `play/stop` осуществляется атомарным флагом `AtomicBool`, новый ритм/темп передаётся через single-producer/single-consumer triple buffer.
- Новый аудиообработчик использует `Output::update()` только на границе такта или при остановленном транспорте и `output_buffer()` для чтения. При публикации нового `PreparedLoop` старый `Vec` освобождается на управляющем потоке, а не в callback.
- Для 15-мс crossfade выделена память при создании проигрывателя. При переключении выполняется ограниченное копирование головы предыдущего такта в уже выделенный буфер.
- Unit-тесты: публикация при остановке, смена только на границе такта, перезапись старых неполученных паттернов, плавный stop/start, изменение длины такта, неверная частота дискретизации. Также сохранены тесты offline-подготовки.
- **Предыдущее прослушивание на Mac относится к старой CPAL-реализации**. Новую версию нужно скомпилировать, прослушать и проверить при быстрых сменах ритма/темпа.
- Синтезированный audio loop по-прежнему предрассчитывается в RAM, без WAV. На сильных CPU это удобно; на Y2 будущие требования могут заставить перейти к синтезу отдельных голосов в callback при сохранении RT-безопасности.

## Полная численная сверка с Magenta.js — 8192 вероятности (2026-11-17)

В текущем `main` добавлены:
- `src/generation.rs::generate_with_observer`: наблюдатель получает *весь* вектор из 512 вероятностей **на каждом шаге обычного Rust-инференса**, без изменения алгоритма генерации.
- `src/verification.rs`: независимая проверка формы, нормировки, версии Magenta.js, checkpoint, отбор Argmax, совпадения 16 классов и сравнение **16 × 512 = 8192 чисел** (максимальная, средняя и RMS абсолютные ошибки, TV distance по каждому шагу).
- `src/bin/verify_reference.rs`: отдельная команда с exit code 1 при выходе за порог `1e-5` или несовпадении классов. Добавлены тесты для последней ячейки, неправильной формы, плохой нормировки и неправильного режима эталона.

**Подтверждено на Mac Studio 2026-11-17:** запущен `verify_reference` с реальным JSON эталона Magenta.js `@magenta/music@1.23.1` (TF.js WebGL): PASS на 8192/8192 вероятностях одной детерминированной Argmax-траектории. На этой траектории все 16 выбранных классов равны 0. Детальные метрики ниже.

### Экспорт Magenta.js и полный тест на Mac Studio

В корне репозитория:

```bash
git pull --ff-only
cargo test --locked --manifest-path experiments/drumsrnn/rust/Cargo.toml
python3 -m http.server 8765 --bind 127.0.0.1
```

В браузере открыть `http://127.0.0.1:8765/experiments/drumsrnn/reference.html`, выбрать **From scratch — no user input** и **Argmax (deterministic)**, нажать **Generate pattern**, затем **Save JSON**. Получится `~/Downloads/drumsrnn-reference.json` (путь может зависеть от настроек браузера).

Из **другого терминала** в корне проекта:

```bash
cargo run --release --locked --manifest-path experiments/drumsrnn/rust/Cargo.toml \
  --bin verify_reference -- --reference "$HOME/Downloads/drumsrnn-reference.json"
```

Сравниватель выводит строки для всех 16 шагов и финальный `PASS` или `FAIL`. Порог по умолчанию `1e-5` абсолютной разницы каждого значения, его можно изменить через `--tolerance`. Файлы эталона/весов в Git не коммитить.

**Границы теста:** при Argmax и тихом служебном входе выбранные классы могут быть нулевыми все 16 шагов, но сравниваются именно все вероятности. Это проверяет **одну детерминированную рекуррентную траекторию**; не доказывает идентичность всех состояний сети, сэмплирования при температуре или разных TF.js backend. Случайные траектории Rust и JS не сопоставимы без принудительной одинаковой последовательности выбранных классов.

### Исправление теста верификации (2026-11-17)

При первой сборке `cargo test --locked` на Mac Studio обнаружен `E0618` в `src/verification.rs`: в тесте `refuses_malformed_shape_and_unnormalized_distribution` локальная переменная `reference` затеняла функцию-хелпер `reference()`. Тест переписан на отдельные переменные `malformed`, `unnormalized` и `wrong_length`; другой код численного сравнения не менялся. **После исправления release-сборка `verify_reference` и полная сверка 8192 вероятностей успешно выполнены пользователем на Mac Studio** (лог приведён ниже); отдельный полный вывод `cargo test` после исправления в данном сообщении не показан.

## Эксперимент — результат полной сверки 8192 вероятностей (Mac Studio, 2026-11-17)

**Статус: PASS, подтверждён пользовательским запуском** `cargo run --release --locked --manifest-path experiments/drumsrnn/rust/Cargo.toml --bin verify_reference -- --reference ~/Downloads/drumsrnn-reference.json`.

| Метрика | Результат |
|---|---:|
| Эталон | Magenta.js `@magenta/music@1.23.1`, TF.js backend `webgl` |
| Модель | `drum_kit_rnn_tfjs` |
| Режим | From scratch, один внутренний тихий шаг, `Argmax` |
| Проверено значений | 16 × 512 = **8192** |
| Максимальная абсолютная ошибка | **1.192092896 × 10⁻⁶** (шаг 2, класс 0) |
| Средняя абсолютная ошибка | **1.529578996 × 10⁻⁹** |
| RMS абсолютной ошибки | **2.754894988 × 10⁻⁸** |
| Порог | **1 × 10⁻⁵** |
| Превышений порога | **0 / 8192** |
| Несовпадений выбранных Argmax-классов | **0 / 16** |

Все 16 классов в обоих движках равнялись нулю, то есть тест выполнен на **одной детерминированной рекуррентной траектории тишины**. Несмотря на это, на каждом шаге сравнивались *все 512 вероятностей*, а не только вероятность класса 0. Следовательно, полнота проверки относится к выходным распределениям **на этой траектории**, а не ко всем возможным траекториям и состояниям модели. Различия не равны нулю побитово и укладываются в численную погрешность двух реализаций (Rust CPU и Magenta.js WebGL).

**Следующий уровень уверенности:** принудительно подать в обе реализации одну и ту же **ненулевую** последовательность предыдущих барабанных классов (teacher-forcing) и сравнить все 512 вероятностей по шагам. Это не меняет требование к пользовательскому режиму — музыка по-прежнему должна генерироваться автономно; ненулевая последовательность нужна исключительно для диагностического теста.
