# Y2Synth — разработка: актуальная сводка и исторический журнал

## Упрощение браузерного UI — только AI-generated

По запросу пользователя HOME стал экраном PLAY/PAUSE с переходом в настройки через OK. Удалены нотная сетка, ручное переключение ударных, USER, возврат демо и стартовые готовые партии. Настройки: AI-GENERATED → PLUCK/PAD/DRUMS, MASTER FX, TEMPO. У PLUCK/PAD сохранены уровни. При пустом проекте PLAY предлагает сгенерировать инструмент, не начинает тихое воспроизведение.

Экран MASTER FX, восемь параметров, их CSS и функции DSP сохранены без изменений. Rust CLI в этом изменении не затронут. Обновлены проверки главного экрана, пустого старта, AI-only маршрутов и навигации колеса; их запуск выполняется Pages CI.

## Актуальный результат — 18 ноября 2026: три нейросетевые модели

По новому заданию пользователя работа возобновлена **в браузере и Rust**:

| Инструмент | Checkpoint |
| --- | --- |
| DRUMS | `drum_kit_rnn` |
| PLUCK | `melody_rnn` |
| PAD | `multitrack_chords` |

### Реализовано

- Браузер: официальный Magenta.js 1.23.1 / TensorFlow.js 2.7.0 в отдельном worker; независимые lazy-модели, статусы загрузки, обработка ошибки/timeout, защита от устаревших ответов, применение новой партии на границе такта. Процедурные AI-генераторы заменены реальными моделями.
- PAD: MusicVAE получает один аккорд из Cm/Eb/Fm/Gm/Ab/Bb; из восьми партий выбирается полифоническая небарабанная, переводится с 96 в 16 шагов/такт и играет нашим PAD. Одновременные ноты сохранены; до шести голосов и 48 нот.
- Rust: streaming-загрузчик float32/uint8/uint16, отбор decoder-тензоров; прямой MelodyRNN 2×512 и MusicVAE conductor/core 3×256 в `neural.rs`. Без JS bridge, без сетевой зависимости во время инференса. Checkpoint заранее скачивается отдельным скриптом.
- Независимый второй Rust SynthTrack для PAD; общий микс DRUMS+PLUCK+PAD перед Delay/Reverb. `dispatch_neural` закрепляет модели за слотами, сохраняет уровень, не меняет другие партии. Генерация и DSP остаются вне callback.
- CLI: `pluck generate`, `pad generate`, `regenerate`, независимые demo/show/clear/level/note. Ошибка модели не закрывает CLI и не стирает музыку. Старый `synth1 pad` направляется в отдельный PAD.
- Downloader поддерживает три выбранных checkpoint; веса не коммитятся. Pages публикует HTML и оба neural JS-файла.

### Что действительно проверено

- [Pages run 44208126649](https://github.com/mvpbit/Y2Synth/actions/runs/44208126649): UI/async-тесты и публикация успешны.
- На опубликованной странице последовательно запущены **настоящие** PAD, PLUCK и DRUMS. UI показал `PAD · Eb · multitrack_chords`, `PLUCK · melody_rnn`, `DRUMS · drum_kit_rnn`; загрузки и генерация завершились.
- [Rust run 44209622695](https://github.com/mvpbit/Y2Synth/actions/runs/44209622695), commit `ab41564`: release `cargo test --locked --features live-audio` — **116 library + 2 CLI = 118 passed**, ошибок нет.
- Официальный Magenta.js в Chromium/CPU использует те же скачанные веса. Rust совпал по **16/16 MelodyRNN Argmax-токенам** с тихого bootstrap и **512/512 MusicVAE Argmax-токенам** с фиксированным latent-вектором и аккордом Cm. Это проверка конкретных траекторий, не всех вероятностей/входов.
- Дополнительно выполнена случайная native-генерация по два раза: PLUCK 1/6 нот, PAD 2/8 нот; партии валидны и различаются. Unit-тесты проверяют квантованные shards, sustain/note-off, полифонию, исключение drums и сохранение обеих дорожек при ошибках.

- Работа выполнена через GitHub; пользовательский локальный checkout не создавался и локальные тесты не запускались.

### Ограничения и следующий шаг

Новая музыка ещё требует прослушивания пользователем на Mac. Производительность/память Y2, xrun и длительная стабильность не измерены. MusicVAE — scalar reference implementation, пригодность для железа не обещается. Браузеру нужен интернет для первого скачивания библиотек/весов; постоянного offline-кэша нет. Generate All и файловое сохранение пока отсутствуют. Browser DSP и Rust DSP разные.

Старые записи ниже сохранены как история. Их утверждения о паузе, процедурной генерации live AI и отсутствии второй дорожки относятся к версии **до этого этапа**.

## Текущий подтверждённый результат на Mac Studio

- **DrumsRNN:** Rust-инференс и автономная генерация; две полные численные сверки Rust vs Magenta.js (тихая Argmax и ненулевая teacher forcing) дали **PASS**: 8192/8192 вероятностей в пределах абсолютной погрешности `1e-5` и 16/16 совпавших Argmax-классов в каждом тесте.
- **Live audio:** CPAL/CoreAudio, `triple_buffer`, общий mono PCM-такт, воспроизведение в реальном времени. Пользователь ранее подтвердил работу live-прототипа.
- **Synth 1:** Pluck (струнная модель) и Pad (аддитивный многоголосный тембр) реализованы и **прослушаны пользователем** — «Работает отлично».
- **Генерация Synth 1:** реализован `src/melody.rs` — автономный **алгоритмический** (не ML) композитор. Путь AI → Generate Track → Synth 1 и `synth1 generate` подключены в коде. Пользователь не предоставлял отдельный отчёт о прослушивании именно автоматически сочинённых партий.
- **Общие мастер-эффекты:** весь сведённый сигнал **Drums + Synth 1 → Master Delay → Master Reverb → Output**. Настройки в `MusicProject.master_fx` сохраняются в RAM-снимке вместе с проектом. Усилена wet-ветвь до `0…1.0` (параллельный `dry + wet × effect`), увеличены отражения Reverb. Пользователь после запуска обновлённого `live` подтвердил: **«Вот теперь всё отлично»**. Считать это подтверждением **звучания**, но не замером RT/CPU.
- **Что отсутствует:** Synth 2, AI Generate All, экран/физические кнопки Y2, файл проекта и восстановление после перезапуска, измеренные xrun/latency, проверка работы на Innioasis Y2. Евклидовы последовательности пока обсуждались, **но не интегрированы**.
- **Полный `cargo test` после последнего усиления FX:** лог не предоставлен. В коде есть unit-тесты, но нельзя утверждать свежий PASS всего набора тестов без результатов запуска.

## Решение о паузе и следующая веха

**Развитие дополнительных музыкальных функций пока поставлено на паузу до приезда Innioasis Y2.** После получения устройства: проверить SoC/ABI, RAM, Linux/Y2Linux, вывод звука, затем тестовую сборку Rust и замеры стоимости DrumsRNN, Synth 1, 12-периодного master-FX pre-roll. Только после этих измерений выбирать оптимизации, стерео FX, экранное меню, постоянное хранение и Synth 2. Не предполагать аппаратную совместимость заранее.

Физический размер на Mac зависит от DPI/zoom. В `main` добавлены `check-ui.mjs` и `.github/workflows/pages-ui.yml`, который на push UI запускает Node-проверку и публикует лишь статический HTML на GitHub Pages. **Первый реальный запуск Actions подтвердил PASS проверки размера и JavaScript**, но deploy остановился на `configure-pages`: сайт Pages в репозитории ещё не активирован (404). **Это не порт DrumsRNN или Rust**, только быстрая интерактивная модель. Генерация DRUMS в браузере процедурная, не модель Magenta; Reverb построен на ConvolverNode, не на Rust comb/all-pass, поэтому совпадение звучания не заявлено. ### Независимые инструменты UI: PLUCK / PAD (18 ноября 2026)

По окончательному решению браузерные инструменты и в UI, и внутри кода называются **PLUCK** и **PAD**, без `synth1`/`synth2`. Из страниц USER убран выбор пресета. ### Сенсорное click-wheel управление по Innioasis Y2 (18 ноября 2026)

В HTML UI Lab три отдельные кнопки PLAY/BACK/HOME и прежние стрелки убраны. Вместо них добавлено единое сенсорное колесо с расположением как в [официальной схеме Y2](https://www.innioasis.com/a/docs/y2/device-overview): **Return сверху, Previous слева, Next справа, Play/Pause снизу, OK по центру**. Моделируется короткое Play/Pause и длинное удержание для Stop и сброса 16-шаговой позиции.

Вращение реализовано через Pointer Events и угол `atan2` от центра кольца: жест на открытой части кольца, с нормализацией ±π при переходе через границу, шаг 22,5°. Поддерживаются touch/mouse pointer и wheel/trackpad. В обычном меню вращение перемещает фокус; на выделенном числовом параметре OK включает `state.editing`, колесо меняет число, повторное OK завершает редактирование. Кнопки Previous/Next дают навигацию, а в edit-mode меняют число; на HOME — шаги паттерна. Вспомогательное управление клавиатурой сохранено.

**Размер дисплея по-прежнему строго 480×360**, физический размер кольца в браузерной модели ориентировочный (340 CSS px относительно 480 CSS px экрана), не аппаратное измерение. Прототип НЕ использует реальные события драйвера Y2. `check-ui.mjs` дополнен DOM/JS smoke-тестом колеса, жеста, редактирования BPM и STOP. **GitHub Actions прошёл, GitHub Pages успешно публикует код из `main`**, однако личное тестирование жеста на устройстве/сенсорном экране ещё предстоит.

### Более вариативная процедурная генерация UI Lab (18 ноября 2026)

По отзыву пользователя переработаны только браузерные генераторы. Предыдущий алгоритм неизменно давал 8 нот PLUCK, 2 аккорда PAD с длиной 8 шагов и snare на шагах 4/12; независимый выбор корня для инструментов также мог разводить партии по тональностям.

Теперь PLUCK создаёт 4–12 нот: меняются плотность, синкопы, паузы, длительности, регистр и направление мелодии (подъём/спуск/арка/шаговый мотив/арпеджио). Опорные ноты учитывают активные аккорды PAD. PAD создаёт 1–4 аккорда с разными моментами смены, трезвучиями, септаккордами, add9/sus, обращениями и открытыми голосами. Обе дорожки используют общий C natural minor, совместимый с демо. Это не гарантирует совпадения каждой старой ноты PLUCK с новым аккордом после отдельной генерации PAD: другая дорожка намеренно сохраняется.

Барабаны выбирают прямой, ломаный, half-time или разреженный рисунок с разной плотностью kick/hat и дополнительными snare/fill. Готовые MIDI-паттерны не используются. Для каждой дорожки хранятся последние 8 сигнатур; максимум 12 попыток уменьшает недавние повторы, без бесконечного перебора. Добавлены velocity нот и их применение в Web Audio; атака PAD ограничена длительностью ноты, в том числе при 240 BPM. Текущий 16-шаговый цикл, меню на английском и геометрия экрана сохранены. **Это процедурный браузерный композитор, не обученная ML-модель и не порт DrumsRNN; Rust не менялся.**

Проверки до публикации выполнены в памяти без локальных файлов: полный набор проверок `check-ui.mjs` через совместимые адаптеры плюс 4 фиксированных seed × 128 генераций каждой дорожки. В каждой серии: 128 разных ритмов PLUCK, 34–40 ритмов смены PAD, 50–56 snare-рисунков, 128 drum-паттернов; проверены границы/сортировка/тональность нот, длительности, velocity, независимость дорожек, сохранность FX/BPM, ограниченность повторных попыток при постоянном RNG и временной порядок аудиоогибающих при 40/120/240 BPM. Эти проверки добавлены в штатный Node/Actions-тест. Слуховая оценка новой версии пользователем ещё предстоит; статистическое разнообразие не является оценкой музыкального качества.

**Проверка публикации:** [Actions #44183870534](https://github.com/mvpbit/Y2Synth/actions/runs/44183870534) завершился успешно: штатный Node-тест и GitHub Pages deploy для `e4d5375` — PASS. На опубликованной странице через настоящие кнопки выполнены три последовательные генерации каждой дорожки во время PLAY: PLUCK показал 8/9/6 нот, PAD 2/3/2 аккорда, kick 6/2/5 и hat 14/4/6 ударов. Web Audio стартовал, счётчик шагов двигался, PAUSE остановил транспорт; в журнале браузера ошибок/предупреждений нет. Это проверка работы, не субъективная оценка звучания.

### Подготовка MelodyRNN для двух инструментов (18 ноября 2026)

Пользователь выбрал `melody_rnn` отдельно для PLUCK и PAD **в браузере и Rust**; PAD сохраняет аккорды через гармонизацию одноголосного результата. Это новое разрешённое направление после прежней паузы. Добавлены выбор checkpoint в `download-model.sh` (по умолчанию прежний DrumsRNN) и GitHub Actions для полного Rust-теста с live-audio и проверки официального MelodyRNN checkpoint. Веса скачиваются только в игнорируемый каталог runner, в Git не добавляются. Интеграция генераторов и проверка численной совместимости ещё в работе.

### Выбранные нейросети и браузерное подключение (18 ноября 2026)

Окончательный выбор пользователя: **DRUMS = drum_kit_rnn, PLUCK = melody_rnn, PAD = multitrack_chords**, для браузера и Rust. Предыдущий план двух MelodyRNN заменён этим решением. PAD получает заданный аккорд из C minor, из многодорожечного результата выбирается полифоническая недрамовая партия. Модель не генерирует тембр: звук остаётся нашим Pluck/Pad.

Браузер использует официальные Magenta.js 1.23.1 и TensorFlow.js 2.7.0 в отдельном Worker, три отдельных экземпляра моделей, ленивую загрузку с официального Google Storage. Веса не коммитятся. MelodyRNN/DrumsRNN стартуют с одного внутреннего тихого шага; PAD использует latent sampling и chord conditioning. Ноты переводятся в C natural minor и рабочий регистр, сетка PAD 24 шага/четверть преобразуется в 4 шага/четверть. Из 8 дорожек выбирается одна полифоническая, число голосов ограничено 6. Браузерные барабаны пока сводят 9 модельных классов к 3 голосам имеющегося Web Audio kit; Rust сохраняет все 9.

Асинхронная генерация не изменяет музыку при сетевой/модельной ошибке, не перезаписывает более свежую USER-правку, во время PLAY публикует результат на следующем такте. Для первого запуска моделей нужен Интернет. Нет скрытого алгоритмического fallback. На тишину/неподходящую PAD-партию предусмотрены максимум три попытки, на зависание — таймаут с освобождением worker. Статические и изолированные runtime-проверки в памяти прошли; штатный Node/Pages CI и реальный запуск моделей проверяются после публикации. Native Rust интеграция ещё выполняется.

**Границы теста:** при Argmax и тихом служебном входе выбранные классы могут быть нулевыми все 16 шагов, но сравниваются именно все вероятности. Это проверяет **одну детерминированную рекуррентную траекторию**; не доказывает идентичность всех состояний сети, сэмплирования при температуре или разных TF.js backend. Случайные траектории Rust и JS не сопоставимы без принудительной одинаковой последовательности выбранных классов.

## Общая мастер-цепочка Delay → Reverb (2026-11-17)

**Приоритет пользователя:** эффекты общие на весь микс, а не по одному на каждом голосе/дорожке. Евклидовы последовательности отложены ради master FX.

Переносимый `src/master_fx.rs` реализует два последовательных эффекта: **(Drums + Synth 1 + будущий Synth 2) → Delay → Reverb → Output**. Delay синхронизирован с BPM (`steps` в 1/16 нотах: 1…8, `feedback` 0…0.75, `wet` 0…1.0). Reverb: четыре comb + два all-pass фильтра (`size` и `damping` 0…1, `wet` 0…1.0). Оба по умолчанию включены; `fx off` отключает оба, не сбрасывая численные настройки. При bypass звук проходит без изменения. Эффекты **моно**, поскольку текущий `PreparedLoop` моно. Стерео и stateful RT processing не заявлены.

Полный такт сперва создаётся в `prepare_project_loop`; затем `ApplicationController::prepare_project` применяет общий `render_master_bar`. Для непрерывных хвостов внутри зацикленного такта выполняется **12 проходов pre-roll** с обратными связями вне audio callback, публикуется итоговый периодический PCM-буфер. При смене FX, BPM, нот, паттернов или кита формируется целый новый бар на control thread. Реальный callback в `realtime.rs` по-прежнему лишь читает `PreparedLoop` и делает короткий crossfade.

`MusicProject.master_fx` хранит единые настройки независимо от дорожек; `ApplicationController::set_master_fx` валидирует диапазоны и применяет их только после успешной публикации. Ошибки не меняют текущую музыку и `last_saved`. Тесты DSP и app покрывают воспроизведение dry/wet, drums-only и synth-only, изменение BPM, сохранение снимка и rollback.

### Усиление слышимости мастер-эффектов (2026-11-17)

После прослушивания пользователь отметил, что оба мастер-эффекта слышны **слишком слабо даже на максимуме**. Причина: прежний закон `dry * (1 - wet) + effect * wet` при увеличении wet заглушал атаку исходной ноты/удара, а внутренняя цепь реверберации дополнительно ослабляла отражения.

В `src/master_fx.rs` изменено:
- **Delay:** `dry + echo * wet`. Исходный удар не становится тише с ростом wet.
- **Reverb:** `dry + diffuse * wet * 1.15`, повышена инжекция в comb-фильтры (`0.3 → 0.8`) и усилена диффузная сумма (`0.25 → 0.5`).
- Диапазон обоих `wet` теперь `0..=1.0`, прежняя общая peak protection `0.85` сохранена.

Тесты дополнены проверкой того, что эхо действительно усиливается при увеличении wet, хвост реверберации заметно растёт по энергии, сухая атака сохраняется, экстремальные настройки не дают NaN/клиппинга и значения wet > 1 отвергаются.

**Код в `main`; пользователь прослушал обновлённую версию на Mac Studio и подтвердил, что теперь звучание устраивает.** Предлагаемый A/B-тест в `y2>`:
